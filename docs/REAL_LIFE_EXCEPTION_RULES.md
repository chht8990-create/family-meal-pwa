# Real-Life Exception Rules v1.0

## RL-001 오늘은 안 먹어요

사용자가 식사 카드의 더보기에서 `오늘은 안 먹어요`를 선택한다.

다음 선택지를 표시한다.

- 외식
- 배달
- 간편식
- 도시락
- 건너뛰기

한 화면에서 하나만 선택한다.

---

## RL-002 외식

- 상태를 dining_out으로 변경
- 예정 레시피 재고 차감 없음
- 비용 입력은 선택
- 기존 식단을 자동으로 다음 날로 이동하지 않음
- 완료 문구: `외식으로 표시했어요.`

---

## RL-003 배달

- 상태를 delivery로 변경
- 재고 차감 없음
- 배달비와 음식값 입력은 선택
- 완료 문구: `배달로 표시했어요.`

---

## RL-004 간편식

- 상태를 convenience로 변경
- 사용한 간편식 재고가 연결되어 있으면 해당 품목만 차감
- 일반 레시피 재료는 차감하지 않음
- 완료 문구: `간편식으로 표시했어요.`

---

## RL-005 도시락

- 상태를 lunchbox로 변경
- 도시락이 재고 품목과 연결된 경우에만 차감
- 완료 문구: `도시락으로 표시했어요.`

---

## RL-006 건너뛰기

- 상태를 skipped로 변경
- 재고 변경 없음
- 비용 변경 없음
- 계획 준수율 감소 같은 평가 없음
- 완료 문구: `이번 식사는 건너뛴 것으로 표시했어요.`

---

## RL-007 메뉴 변경

1. 기존 MealPlan을 replaced로 변경
2. replacementGroupId 생성
3. 새 MealPlan을 planned로 생성
4. 새 레시피 기준 부족 재료 재계산
5. 기존 레시피 재고 차감 없음

사용자에게 기존 메뉴를 다른 날짜로 이동할지 자동으로 묻지 않는다.
별도 동작으로 제공한다.

---

## RL-008 이미 조리 완료한 메뉴 변경

기본적으로 금지한다.

사용자는 먼저 조리 완료를 Undo한 뒤 메뉴를 변경해야 한다.
이렇게 해야 재고 복구와 상태 변경 순서가 명확해진다.

---

## RL-009 비용 입력

외식·배달·간편식·도시락에서 비용 입력은 선택 사항이다.

- 지금 입력
- 나중에
- 입력 안 함

비용 입력 화면을 강제로 열지 않는다.
