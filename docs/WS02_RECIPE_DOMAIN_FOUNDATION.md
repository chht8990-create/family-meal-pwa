# WS-02 — Recipe Domain Foundation v1.0

## 1. 목적

HomeOS의 레시피를 화면에 표시되는 문자열 묶음이 아니라, 식단·장보기·재고·조리 모드·추천이 공통으로 사용하는 핵심 도메인 객체로 재설계한다.

WS-02의 핵심 원칙은 다음과 같다.

> 레시피는 복사 가능한 글이 아니라 재사용 가능한 데이터여야 한다.

## 4. 핵심 설계 결정

### 4.1 재료와 양념은 같은 IngredientLine 구조를 사용한다

`group` 값으로 구분한다.

- main
- seasoning
- garnish
- optional

이렇게 하면 장보기·재고 차감 로직을 하나로 유지할 수 있다.

### 4.2 인원 환산은 재료마다 다르게 적용한다

모든 재료를 단순 비례로 늘리지 않는다.

지원 방식:

- linear: 인원에 정확히 비례
- gentle: 완만하게 증가
- minimal: 아주 적게 증가
- capped: 상한선 적용
- fixed: 고정량
- discrete: 개수 단위로 반올림

### 4.3 레시피 신뢰도는 숫자 하나로 단정하지 않는다

`confidence: 95%`처럼 과도하게 정밀한 표현은 사용하지 않는다.

대신 검증 상태를 사용한다.

- draft
- tested_once
- tested_multiple
- household_verified
- official_reviewed

사용자 화면에는 필요한 경우 다음처럼 표현한다.

- 시험 조리 전
- 실제 조리 확인
- 여러 번 조리 확인
- 가정 사용 검증
- HomeOS 검토 완료

### 4.4 버전은 변경 이력을 추적한다

- version: semantic version
- revisionNotes
- updatedAt
- previousVersionId

레시피 수정은 기존 버전을 덮어쓰지 않고 변경 사유를 남긴다.

### 4.5 영양정보는 선택 항목이다

정확한 출처가 없는 영양정보는 표시하지 않는다.
MVP에서는 필수 항목이 아니다.

## 5. 최소 품질 기준

공식 또는 추천 레시피가 되려면 다음을 모두 충족해야 한다.

- 제목
- 기준 인원
- 총 조리시간
- 난이도
- 재료 수량과 단위
- 준비 단계
- 순서가 있는 조리 단계
- 각 핵심 단계의 불 세기 또는 가열 기준
- 실패 방지 팁
- 보관법
- 알레르기 또는 주의 정보
- 검증 상태
- 버전

---

## 6. 완료 기준

- Recipe JSON Schema 작성
- Ingredient 및 단위 규칙 작성
- 2~10인분 환산 함수 정의
- 샘플 레시피 3개 작성
- 품질 검증 체크리스트 작성
- 기존 프로토타입 데이터의 마이그레이션 계획 작성
- 조리 완료 시 재고 차감에 사용할 필드 확정
